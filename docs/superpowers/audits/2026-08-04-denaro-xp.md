## Approved invariants

These architectural contracts are normative (STEERING §22) and every matrix row is judged against them:

- Handlers and lifecycle callers own `commit`; services never commit (sole documented exception: shop
  audit trail).
- Money decisions and arithmetic run in SQL: predicate in `WHERE`, relative arithmetic in `SET`
  (`coins = coins + :delta`), `rowcount == 0` means the race was lost, always with
  `.execution_options(synchronize_session=False)` followed by a targeted refresh.
- Reads of decisive values prefer columns over potentially stale ORM entities; never
  `populate_existing=True`, never `session.expire` (async `MissingGreenlet`).
- Locks are used only when atomic SQL is insufficient; canonical order Event → User → Wallet, wallets
  locked by ascending `tg_id`.
- `User.xp` mutates only through `xp_service`; every XP source keeps its capped/uncapped
  classification (recorded in STEERING §12.1).
- Preserved: amounts, prizes, costs, payout formulas, caps, capped/uncapped classifications, ranks,
  thresholds, and every current gameplay outcome. Rebalancing is out of scope.
- `TEST_PG_URL` is only ever the dedicated throwaway container; `DB_URL` and the Compose `gamingbot`
  database are never used by tests. The fixture refuses any database not ending in `_test`.
- A fix requires a focused test observed RED; no production change from inspection alone. Verified-safe
  paths are documented and not rewritten for stylistic uniformity.
